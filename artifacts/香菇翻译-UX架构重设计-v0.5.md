# 香菇翻译 UX 架构重设计（v0.4 → v0.5 提案）

- 作者角色：用户体验架构师（ArchitectUX）
- 基线：PRD v0.4 交付基线（2026-08-21）+ `extension/` v0.4.0 实际代码
- 文档性质：UX 架构与交互规格，供开发实施；不改变 PRD 的权限、隐私与技术栈决策

## 1. 诊断：五个体验断点

| # | 断点 | 现状证据 | 影响 |
| --- | --- | --- | --- |
| B1 | 引导即完整设置表单 | `panel.html` 设置工作区复用为首引导，「开始连接」标题下 6+ 字段一屏铺开 | 新用户认知负担过重，首配流失 |
| B2 | 首次信心链断裂 | 「测试翻译」是设置内的独立动作，向导流程中无内联验证 | `/models` 成功≠可调用，用户带着未验证配置进入翻译 |
| B3 | 语言心流中断 | 自定义目标语言只能在设置中创建（PRD 7.7） | 主界面切换小语种/风格语言必须离开翻译现场 |
| B4 | 双面板孤岛 | Popup 与 Side Panel 草稿/最近结果按面板独立（PRD 6 决策表） | 用户心智是"我的翻译"，换入口即丢上下文 |
| B5 | 错误无恢复闭环 | 错误仅分类文案提示；`app.js` 中 `settingsButton` 同时承担齿轮/返回两个角色，无导航上下文 | 用户需自行"进设置→找字段→改→找路返回→手动重试" |

## 2. 架构原则

1. **一个路由核心**：工作区显隐从分散判断收敛为纯函数 `workspace = f(入口, 配置完整度, 导航上下文)`。
2. **三层状态**：配置层（`storage.local`，全局共享）/ 会话层（`storage.session`，按面板独立，沿用 PRD 决策）/ 瞬态层（进行中请求，面板关闭即取消）。
3. **就地降级**：任何失败路径都在当前场景内消化（手动填模型、跳过测试），不把用户抛到别处。
4. **自动返程**：任何离开翻译态的路径都记忆来路，完成后自动返回并续上被中断的操作（重译/继续输入）。
5. **视觉系统零重构**：现有 `css/panel.css` 的冷白底、菌盖绿、组件 token 全部沿用，本方案只动信息架构与状态流。

## 3. 工作区路由状态机

### 3.1 状态定义

```ts
type Entry = "popup" | "sidepanel" | "options";

type Workspace = "onboarding" | "translate" | "settings";

interface NavContext {
  from: "first-run" | "error-recovery" | "model-switch" | "manual" | "options-entry";
  /** error-recovery 时：需要高亮定位的设置字段 id */
  focusField?: string;
  /** 返回翻译态后是否自动重译 */
  autoRetry?: boolean;
}

interface RouteInput {
  entry: Entry;
  configComplete: boolean;   // 服务商+模型+目标语言齐备（Ollama Key 可空）
  nav: NavContext | null;    // null = 无进行中的导航
}
```

### 3.2 路由规则（纯函数）

```
route(input):
  if entry === "options"            → "settings"（隐藏翻译/设置切换，沿用 PRD 12.4）
  if !configComplete                → "onboarding"
  if nav === null                   → "translate"
  if nav.from === "manual" 等        → "settings"
```

### 3.3 关键迁移

| 迁移 | 触发 | 行为 |
| --- | --- | --- |
| onboarding → translate | 向导第 4 步「开始使用」 | 保存配置，`nav = null` |
| translate → settings | ① 错误卡片「修复」② 底部模型快捷条 ③ 齿轮 | 写入 `nav`（含 `focusField` / `autoRetry`）；设置按钮切换为返回箭头（现有 `is-back` 样式沿用） |
| settings → translate | 保存成功 且 `nav !== null` | 自动返回；`nav.autoRetry` 为真时用最近原文快照自动重译 |
| settings → translate | 保存成功 且 `nav === null`（手动进入） | 现状行为：返回翻译界面 |

**不变量**：同一时刻仅一个工作区；状态消息在两个工作区均可见；Options 恒为设置态——三条 PRD 约束全部保留。

## 4. 规格 A：首次引导三步向导（解决 B1 + B2）

向导是设置态的**一种视图模式**（`settingsMode: "wizard" | "manager"`），与日常设置共用同一批表单组件与校验逻辑，只是分步呈现。

### 步骤设计（420×600 弹窗内）

| 步 | 内容 | 完成条件 | 失败降级（就地，不离场） |
| --- | --- | --- | --- |
| ① 连接 | 服务商选择（自动填 Base URL）+ API Key（Ollama 跳过） | 必填项合法 | — |
| ② 模型 | 「获取模型」→ 下拉选择；或直接手动填写 | 模型非空 | `/models` 失败 → 自动切换为手动输入，保留已填值（沿用 PRD 7.1） |
| ③ 验证 | 内联「测试翻译」：固定短句真译一次，显示返回的短译文 | 测试通过（可选步骤，可「跳过」） | 测试失败 → 显示错误分类 + 「上一步修改」，可跳过但明示风险 |
| ④ 确认 | 目标语言（默认英语）+「开始使用」 | 保存成功 | 保存被阻止时字段级提示 |

要点：
- 步骤条常显（①②③④），已完成步骤可点击回退修改，进度不丢。
- 第③步把「测试翻译」从设置深处**前置到向导内联**，补上首次信心链。
- 向导期间隐藏齿轮按钮（现状 `app.js` 1175 行已做，保留）。

## 5. 规格 B：错误恢复闭环（解决 B5）

### 错误卡片结构（替换现有纯文本状态区）

```
[分类标签]  鉴权失败
原因文案：API Key 无效或已过期（服务商返回 401）
[去修复]   [重试]
```

- 分类标签沿用 PRD 9.4 五类：配置/网络/鉴权/模型/权限。
- 「去修复」：写入 `nav = { from: "error-recovery", focusField: <字段id>, autoRetry: true }` 并路由到设置态；设置态滚动到目标卡片并高亮字段（2 秒渐隐高亮，遵守 `prefers-reduced-motion`）。
- 「重试」：就地用原文快照重译，不跳转。
- 保存成功自动返回翻译态并自动重译（见 3.3）。

### 字段映射表

| 错误分类 | focusField |
| --- | --- |
| 配置问题（模型为空等） | `#model` |
| 鉴权问题 | `#apiKey` |
| 权限问题（自定义地址未授权） | `#baseUrl` |
| 网络问题（Base URL 不可达） | `#baseUrl` |
| 模型问题 | `#model` |

## 6. 规格 C：目标语言内联创建（解决 B3）

- 主界面目标语言选择器列表底部固定「＋ 自定义语言…」项。
- 选中后弹出面板内小表单（名称输入 + 保存/取消），保存后立即写入配置 `targetLanguage.custom` 并选中，输入焦点回到原文框。
- 不离开翻译态、不清空草稿；设置页保留完整管理入口（重命名/删除）。
- 不改变「自定义语言不参与交换」的 PRD 规则。

## 7. 双面板孤岛的处理（B4，克制方案）

面板独立是 PRD 的明确隐私决策（session 存储、退出即清），**v0.5 不改为共享**，仅补一条心智提示：

- 检测到另一面板会话存在未完成草稿时，在空面板顶部显示一次性轻提示：「另一窗口有未完成的翻译 → 在浏览器会话内不可跨面板同步」。
- 「跨面板草稿接续（用户显式导出/导入）」列入二期候选，不做自动同步。

## 9. 验收清单（补充到 PRD 12）

- 首次打开进入三步向导；每一步可独立失败并就地降级，进度可回退。
- 向导第③步成功显示短译文后才出现「开始使用」的高置信路径；跳过测试有明示。
- 错误卡片「去修复」后：设置态定位并高亮对应字段；保存后自动返回翻译态并自动重译。
- 错误卡片「重试」就地生效，不发生工作区切换。
- 主界面创建自定义语言 ≤2 次点击，草稿不清空。
- Options 入口行为与现状一致（恒设置态、隐藏切换按钮）。
- 320px 宽度下向导与错误卡片无横向溢出；高亮动画在减少动态效果设置下关闭。
